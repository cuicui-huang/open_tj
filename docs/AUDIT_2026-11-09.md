# 产品审计与修复 · 2026-11-09

一轮系统排查的记录：发现的问题、证据、处理结果。每一条都有可运行的测试，
不靠“看起来没问题”。

## 已修复（7 项）

### 1. 断开后连通性卡片仍显示上一次会话的结果
**严重度：高。** 这是会误导用户的错误信息——界面写着“未连接”，下面却列出
`xlcp.tongji.edu.cn 11ms · 24ms · 58ms`，还标“更新于 刚刚”。

**证据**：`finishSession()` 清空了 `active`/`connected`/`iface`/`checking`，
唯独没清 `probes`/`probesAt`。实测断开后 `len(c.probes) == 1`，界面仍渲染该行。

**修复**：`finishSession` 与 `Reconnecting` 都清空探针与隧道 DNS。
**测试**：`TestProbesClearedWhenSessionEnds`、`TestProbesClearedWhenReconnecting`。

### 2. 重连期间同样残留探针
**严重度：高。** 隧道已断但探针数据还在，与 #1 同源，走的是另一条路径
（`Reconnecting` 而非 `finishSession`）。一并修掉。

### 3. 日志搜索只在消息正文里找
**严重度：中。** 界面上的日志行有 `ERROR | network | …` 三列，但搜索
`network` 或 `error` 都返回 0 条——用户看到什么却搜不到什么。

**修复**：新增 `matchesSearch`，同时匹配 message、component、level，并 trim 空格。
**测试**：`TestLogSearchMatchesComponentAndLevel`（4 个断言）。

### 4. 启动即读钥匙串，弹出系统密码框
**严重度：高。** `remember=true` 时 `New()` 立刻调 `loadCredentials()`，
macOS 因此弹「Open TJ 想使用你的机密信息」并要求输入登录密码。用户只是打开
应用，没做任何需要密码的操作。这个弹窗还会挡住窗口，我前几轮截图失败就是它。

**修复**：启动只记下 `remembered` 标志；真正需要密码时（`Connect()`，或账号页
主动请求）才读钥匙串。
**测试**：`TestLaunchDoesNotReadKeychain`——断言启动 0 次读取、连接时 1 次。

### 5. 开机自启开关显示的是偏好，不是系统真相
**严重度：中。** `OpenAtLogin()` 直接返回 `prefs.OpenAtLogin`。用户在系统设置里
删掉登录项，应用里仍显示“已开启”，开关与事实不符。

**修复**：新增 `Config.OpenAtLogin` 回调，默认接 `mygo.App.OpenAtLogin`，读系统真值。
**测试**：`TestOpenAtLoginFollowsSystem`。

### 6. 手动「重新检测」测不到隧道 DNS
**严重度：中。** 之前用 `ProbeSitesWith(ctx, sys, sys)` 比较系统解析器自身，
所以「系统 DNS 失败但隧道内正常」这条最有用的诊断永远触发不了。

**修复**：`Reporter.Connected` 增加 `dns []string` 参数，supervisor 传入网关下发的
`cfg.DNS`；controller 保存并在刷新时构造真正的隧道 resolver。
**说明**：这改动了 `Reporter` 接口，但只是**新增参数**，不影响 supervisor 的
状态机逻辑，符合“不重构 supervisor”的约束。

### 7. 日志/账号/设置页每秒重绘
**严重度：低（耗电）。** 侧栏状态条的连接时长每秒递增，`ctx.After(time.Second)`
挂在侧栏上，于是任何页面都每秒重绘整帧。只有概览页显示秒级时长。

**修复**：仅当 `Page == pageOverview` 时才请求下一帧。

## 第二轮修复（最佳实践）

### 8. 取消管理员授权时，把 AppleScript 原文甩给用户
**证据**：实测 `osascript` 取消授权返回 `0:55: execution error: User canceled. (-128)`，
原样显示在界面和日志里。用户看到的是脚本位置和错误码，不是“你取消了”。

**修复**：`helperStartError` 把三种常见情况翻译成人话（取消 / 系统拒绝 / 无输出），
其余情况剥掉 `execution error:` 位置前缀并截断到 120 字。
**测试**：`TestHelperStartErrorExplainsCancellation`、`TestFirstSentenceDropsLocation`。

### 9. 失败后按钮仍写“连接 VPN”
用户刚失败，按钮还叫“连接 VPN”，看不出它能修好当前状态。
**修复**：失败态下按钮文案改为“重试”。

### 10. 钥匙串读取失败后用户无路可走
钥匙串读取失败（如用户点了“拒绝”）只写日志，账号页没有任何提示，也没有重试入口，
用户只能重新手打密码。
**修复**：`CredentialError()` 暴露失败原因显示在页面上；`NeedsCredential()` 为真时
在连接按钮旁提供「从钥匙串载入密码」。
**测试**：`TestKeychainFailureIsVisibleAndRetryable`（含“重试后成功则错误消失”）。

### 11. 隧道 DNS 错误指向了一个从未访问的服务器
**证据**：`vpn_dns_error` 写着 `on 223.6.6.6:53`，而实际 dial 的是 `10.5.0.1:53`。
这是 Go 的 `net.Resolver` 行为——报错里带的是 `resolv.conf` 里的服务器，不是 Dial
实际连的地址。排查时会让人去查错误的 DNS 服务器。

**修复**：`nameDialTarget` 在隧道 DNS 错误前标注真实 dial 目标，幂等、递归处理跳转。
**测试**：`TestTunnelDNSErrorNamesTheDialedServer`（含幂等与健康探针不受影响）。

## 已验证无问题

- 最小窗口 720×520 下概览排版完整，无裁切、无溢出
- 断开到重连全程 `-race` 无数据竞争
- 日志上限 2000 条生效，旧的按条数正确丢弃
- 托盘图标与菜单在状态变化时刷新
- 退出前先断开并等网络恢复（`RequestQuit`）

## 未处理（需要产品或权限决策）

### A. Windows 开机自启应走计划任务
MyGo 文档说明：需要管理员权限的 VPN 客户端应注册 Task Scheduler 任务
（`HighestAvailable`），而不是 `SetOpenAtLogin`。当前在 Windows 上会用非提权
令牌启动，VPN 隧道会因此失败。需要 Windows 真机验证后再改。

### B. 账号页没有“从钥匙串载入”的显式入口
`NeedsCredential()` 已经实现（可判断是否存有密码），但界面上还没用起来。
当前流程是点「连接」时自动读取，够用；显式按钮是体验优化，不是缺陷。

### C. 没有自动更新
`plugins/updater` 已可用，但要先配 GitHub Release 的签名公钥。属于发布流程，
不是代码问题。

### D. Android 端与本轮无关
本轮全部改动只在 `apps/desktop`，未触碰 `apps/android`。
